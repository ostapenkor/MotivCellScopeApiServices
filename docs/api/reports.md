# Отчёты

Описание реализации на коммите `db7f93001de5e57b710cad7a03cb716e706a8a0d`. Файл называется `ReportController.cs`, но класс — `ReportsController`; шаблон `api/[controller]` задаёт базовый путь **`/api/reports`**. Все три маршрута требуют любой валидный JWT: `[Authorize]` без ограничения роли. Источник: [ReportController.cs:10–23][reports-class].

Общие правила Bearer-токена, стандартных `400`/`401`/`415` и необработанных `500` описаны в [авторизации](auth-reference-health.md#общие-правила). Здесь нет специальных ограничений для `engineer`, `operator` или `admin`, поэтому все три роли имеют одинаковый доступ.

## GET /api/reports/summary

Считает число инцидентов и количество записей по категориям и важности. Источник: [ReportController.cs:24–54][summary]. Тела запроса нет.

| Query-параметр | Тип | Обязательность и умолчание | Условие выборки |
|---|---|---|---|
| `from` | `DateTime?`, строка даты/времени, распознаваемая model binder | Необязателен; без него нижней границы нет. | `BeginTime >= from.Value` |
| `to` | `DateTime?`, строка даты/времени | Необязателен; без него верхней границы нет. | `BeginTime <= to.Value` |

Один параметр можно передать без другого. Обе границы включительны, отбор идёт только по времени **начала**, не по пересечению длительности. `from > to` не валидируется отдельно: запрос обычно вернёт пустой результат. Метод не вызывает `ToUniversalTime()`; сравнивает значения, полученные привязкой `DateTime`. Строгой проверки обязательного смещения/`Z` нет; в комментарии к коду приведены и даты без времени. Для устранения неоднозначности клиенту удобно передавать UTC с `Z`, например `?from=2026-11-01T00:00:00Z&to=2026-11-30T23:59:59Z`.

Без обеих дат используется вся таблица; периода «последние 30 дней» нет. Другие query-параметры, включая `groupBy`, `category`, `severity`, ID справочников, поиск и пагинацию, метод не использует.

`200 OK`, точная форма:

```json
{
  "total": 3,
  "byCategory": [
    {"category":"power","count":2},
    {"category":"transport","count":1}
  ],
  "bySeverity": [
    {"severity":"medium","count":1},
    {"severity":"high","count":2}
  ]
}
```

`total`, `count` — целые числа; `category`, `severity` — строки из записей БД. Массивы содержат только встретившиеся группы, без добавления нулевых групп и без заданной сортировки. Пустой результат:

```json
{"total":0,"byCategory":[],"bySeverity":[]}
```

Полей периода, сумм простоя, количества исключённых записей, групп по направлению/ТЦ/типу аварии в ответе нет. Запросы total и двух групп выполняются отдельно; общей транзакции чтения метод не создаёт.

Ошибки: неразбираемая дата — стандартный `400` до входа в метод; нет валидного JWT — `401`; необработанная ошибка БД/выполнения — возможный `500` без заданного здесь JSON. Специальных `404`/`409` и собственного объекта ошибки метод не формирует.

## GET /api/reports/available-periods

Возвращает самую раннюю и позднюю даты **начала** инцидента во всей таблице. Query-параметров и тела нет. Источник: [ReportController.cs:56–76][periods].

`200 OK`, пример с данными:

```json
{"minBeginTime":"2026-10-12T08:30:00","maxBeginTime":"2026-11-14T19:05:00"}
```

Оба поля — стандартно сериализованные `DateTime`, а не вручную форматированные строки `...Z`. Метод возвращает значения `Min/Max` из EF без изменения `Kind` или преобразования в UTC; наличие суффикса/дробных секунд зависит от значений `DateTime`. Пример без `Z` не означает выполнение отдельного преобразования в локальное время.

Если таблица пуста, также `200 OK`:

```json
{"minBeginTime":null,"maxBeginTime":null}
```

Ровно два свойства; `from`, `to`, `total`, `months` отсутствуют. Это не границы по `endTime`, не список месяцев и не календарь непрерывной доступности данных. `Any`, `Min` и `Max` вызываются отдельно. Ошибки: общие `401` и возможный необработанный `500`; специальных `400`/`404` нет.

## GET /api/reports/export

Выгружает записи инцидентов, а не агрегированные группы. Входы `from`/`to` полностью совпадают с `summary`: обе даты необязательны, применяются независимо и включительно к `BeginTime`, без явного `ToUniversalTime()` и проверки порядка. Без дат выгружается вся таблица. Тела запроса нет. Источник: [ReportController.cs:78–107][export].

`200 OK` возвращает файл, не JSON:

- `Content-Type: text/csv`.
- Имя `report_yyyyMMdd.csv`, где дата — `DateTime.UtcNow` во время формирования ответа, например `report_20261115.csv`.
- UTF-8 **с BOM**: `Encoding.UTF8.GetPreamble()` явно добавляется к байтам содержимого.
- Разделитель `;`; строки формирует `StringBuilder.AppendLine`, поэтому перевод строки определяется платформой приложения.
- Порядок записей: `BeginTime` по убыванию, дополнительный порядок при одинаковом времени не задан. Все выбранные записи, без пагинации.

Точный заголовок, 9 столбцов:

```csv
ID;PW;Описание;Начало;Окончание;Длительность;Общий простой;Категория;Важность
```

| № | Столбец | Значение |
|---|---|---|
| 1 | `ID` | `IncidentId` |
| 2 | `PW` | `Pw` как есть |
| 3 | `Описание` | `Descr`, в котором `;` заменяется на `,`; при null пустая строка |
| 4 | `Начало` | `BeginTime` в `yyyy-MM-dd HH:mm`, без секунд и смещения |
| 5 | `Окончание` | `EndTime` в том же формате; при null пусто |
| 6 | `Длительность` | Сохранённое `Lenght` |
| 7 | `Общий простой` | Сохранённое `CommonProstoy` |
| 8 | `Категория` | `Category` |
| 9 | `Важность` | `Severity` |

Пример содержимого после BOM:

```csv
ID;PW;Описание;Начало;Окончание;Длительность;Общий простой;Категория;Важность
42;PW-42;Отключение, восстановлено;2026-11-14 08:00;2026-11-14 09:00;0 days, 01:00:00;0 days, 01:00:00;power;high
```

Общего CSV-экранирования в этом методе нет: кавычки и переводы строк не обрабатываются, `;` заменяется только внутри `Descr`, значения с формулами не нейтрализуются. Остальные nullable-поля при строковой интерполяции дают пустые ячейки. Вычислений длительности или простоя при экспорте нет: берутся сохранённые строки. Формат и состав отличаются от [CSV `/api/incidents/export`](incidents.md#get-apiincidentsexport).

Перед ответом вызывается `_audit.Log("export_report", "report", null)`. Ошибка записи аудита перехватывается сервисом и не отменяет выдачу файла. Источник: [AuditService.cs:53–122][audit]. Ошибки самого метода: стандартный `400` для неразбираемой даты; `401` без JWT; возможный необработанный `500` при чтении БД/формировании результата. Собственных специальных объектов ошибок нет.

## Покрытие и отличия от предложенного контракта

Описаны все **3** атрибутных маршрута `ReportsController`. В этой версии отсутствуют `/api/reports/incidents-summary`, `/api/reports/incidents-export`, `/api/reports/events`; алиасов для них нет. Сводка доступна по `/summary`; экспорт — 9 столбцов с исходными инцидентами, без `groupBy` и сумм простоя. Это описание текущего поведения, а не перечень предлагаемых изменений.
