## Сценарий демонстрации через Swagger: 90 секунд

### Подготовка до выступления

- Развернуть отдельную тестовую базу с актуальной схемой и убедиться, что API отвечает. На этой задаче запуск приложения не выполнялся, поэтому открытие Swagger нужно проверить заранее.
- Swagger подключается в `Program.cs` только при `ASPNETCORE_ENVIRONMENT=Development`. Использовать фактический адрес, полученный при запуске, с путём `/swagger`. Не обещать, что он автоматически доступен в Production.
- Выполнить `/api/health`: перед защитой ожидается HTTP 200 и `database: "ok"`. Это проверка соединения, а не промышленный мониторинг SLA.
- Подготовить тестовую учётную запись `admin` либо `operator`; для последнего просмотра аудита нужен именно admin. Не включать действительные пароли и токен в слайды.
- Заранее получить `/api/reference/all` и подобрать существующие ID. Предзаполнить JSON создания и изменения, чтобы не печатать его перед жюри.
- Пометить событие текстом `ДЕМО ЗАЩИТЫ`. Использовать дату начала в прошлом и тот же период во всех последующих запросах. Сохранить ID, полученный из ответа создания.
- После защиты удалить только это тестовое событие, если оно больше не нужно. Не запускать `init.sql` для «быстрой очистки»: он начинается с `DROP DATABASE IF EXISTS motiv_report`.

### Ход показа

| Время | Действие | Готовая реплика |
|---|---|---|
| 0–15 сек | POST `/api/auth/login`, вставить token в Authorize | «Входим в API. Токен содержит идентификатор и роль пользователя» |
| 15–25 сек | GET `/api/auth/me` и ранее подготовленный ответ `/api/reference/all` | «Сервер возвращает нашу роль и общие справочники для заполнения события» |
| 25–45 сек | POST `/api/incidents` с готовым JSON | «Создаём отдельную тестовую аварию. Ответ 201 содержит номер новой записи» |
| 45–60 сек | PUT `/api/incidents/{полученный ID}` с полным JSON и endTime | «Указываем окончание. Сервер сохраняет обновлённое событие» |

## Честные границы текущего main

Этот список предназначен для подготовки и ответов на вопросы. На девятом слайде достаточно двух коротких пунктов.

- В этой ветке нет исходников готового PHP-сайта и отдельного HTML/CSS/JS-клиента. `Program.cs` подключает контроллеры и Swagger, но не раздаёт `wwwroot`.
- В POST/PUT `IncidentsController` поле `CommonProstoy` получает `formattedDuration`. Формула PDF «простой одной БС × количество БС» таким присваиванием не реализована. Не утверждать обратное.
- Для НВ `end_time` хранится как SQL NULL, хотя PDF описывает нулевую дату. Длительность рассчитывается при POST/PUT и хранится строкой. Непрерывное обновление этой строки при простом GET не реализовано.
- Выборка списка и подробного CSV идёт по `BeginTime >= from && BeginTime <= to`, а не по пересечению аварии с периодом. Старое незавершённое событие с началом вне выбранного диапазона туда не попадёт.
- В API operator и admin могут удалять события. Ограничение удаления только администратором в этой версии отсутствует.
- Подробный CSV — `/api/incidents/export` (23 колонки, включая расширения). `/api/reports/export` — сокращённый отчёт. Не смешивать их описание.
- Аудит пишется после сохранения основной операции отдельным вызовом. Ошибка аудита логируется, но это не атомарная неизменяемая история всех версий.
- В `MonitoringController` есть допущения расчёта: средние почасовые проценты, трафик с делителем 1024³, доступность по наличию попыток, значение 100 при отсутствии строк. До отдельной верификации нельзя трактовать их как доказательство реальной доступности/SLA.
- Результаты прежних тестовых наборов других веток не доказывают работу этого коммита. Конкретный Chrome 75, нагрузочное испытание и production-развёртывание здесь не подтверждались.

## Вероятные вопросы жюри

**Почему вы показываете Swagger, а не сайт?**

«В текущем main готова серверная часть. Swagger позволяет проверить реальные запросы, роли и ответы без имитации интерфейса. Отдельный браузерный клиент нужно подключить к этому API. Мы не выдаём Swagger за законченный пользовательский сайт».

**Чем таблицы лучше одного Excel-файла?**

«В базе у события есть идентификатор, связи со справочниками и автором. Пользователи работают через общий API, а важные действия попадают в аудит. При этом мы пока не измеряли экономию времени и не называем выдуманный процент улучшения».

**Как защищён доступ?**

«Сервер проверяет BCrypt-хеш пароля, выдаёт JWT на два часа и проверяет роль на защищённых методах. Инженер читает, operator работает с событиями, admin управляет пользователями и аудитом. Защиту промышленного контура нужно дополнять настройкой HTTPS и регламентами эксплуатации».

**Где 19 полей из задания?**

«Они представлены данными incidents и связанными справочниками. Например, направление и ТЦ хранятся через внешние ключи, а при чтении представление возвращает их коды. Схема нормализована, поэтому физические столбцы не повторяют плоский список PDF буквально».

**Категория 1–3 и category=power — одно и то же?**

«Нет. Числовая категория и исходные коды приоритета находятся в incident_priorities и возвращаются как priorityCode. Поле category отдельно классифицирует причину события: power, transport и другие. Это нужно ясно подписать в будущем интерфейсе».

**Что происходит с незавершённой аварией?**

«В текущем коде отсутствие окончания хранится как NULL. При сохранении длительность считается до текущего времени. Автоматический пересчёт при каждом чтении и согласование способа хранения НВ с PDF ещё нужно завершить».

**Правильно ли считается общий простой?**

«В текущем коммите есть ошибка: в commonProstoy копируется длительность события. Мы её выявили при проверке соответствия заданию. Перед использованием отчёта это нужно заменить на простой одной БС, умноженный на количество БС, с отдельным правилом для сектора».

**Какие тесты уже прошли?**

«Для этой защиты мы должны назвать только выполненные проверки именно текущего main и показать их результаты. Само наличие методов в коде не заменяет тестирование. Числа из прежних экспериментальных веток к текущему коммиту мы не относим».

**Можно ли применять проект сразу в рабочей сети?**

«Пока это прототип. До эксплуатации нужны исправление расчётов, законченный веб-клиент, приёмочные проверки, резервное копирование и настройка защищённого доступа. Наличие Docker упрощает состав развёртывания, но само по себе не гарантирует промышленную готовность».
