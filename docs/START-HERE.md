# Запуск новой ветки kolya-api-sync

Эта ветка создана от последнего main на момент начала работы: `aff0a9f`. Она использует **новую схему коллеги и MariaDB 10.1**. Старый PHP-макет из KOLYA не смешивается с API: весь работающий сайт теперь находится в папке `php-site/`.

Репозиторий: https://github.com/ostapenkor/MotivCellScopeApiServices

## Что установлено на компьютере

Нужны Git и Docker Desktop с запущенным Linux engine. PHP, .NET SDK, MariaDB, Python, npm и Visual Studio для самого запуска устанавливать не требуется: API, сайт и БД работают в контейнерах.

```powershell
git --version
docker version
docker compose version
```

## Скачать именно новую ветку

Для отдельной чистой копии:

```powershell
git clone --branch kolya-api-sync https://github.com/ostapenkor/MotivCellScopeApiServices.git MotivSync
cd MotivSync
git branch --show-current
```

Должно быть `kolya-api-sync`. Если рабочая копия уже есть и свои изменения сохранены:

```powershell
git fetch origin
git switch kolya-api-sync
git pull --ff-only origin kolya-api-sync
```

При несохранённых изменениях сначала сохраните свою работу. Для просмотра можно использовать отдельный клон вместо принудительного сброса файлов. В main эта ветка автоматически не объединяется.

## Настроить локальные секреты

Из корня репозитория:

```powershell
Copy-Item .env.example .env
notepad .env
```

Замените значения `DB_ROOT_PASSWORD`, `DB_PASSWORD` и `JWT_SECRET_KEY` собственными. JWT-ключ — случайная строка не короче 32 символов. `DB_USER=motiv_app` можно оставить. Значения не должны содержать переводы строк; для простого .env удобно использовать случайные латинские буквы, цифры и `_`/`-`. Файл `.env` игнорируется Git.

Пароли БД и JWT-ключ **не являются паролями сайта**. Логины сайта существуют в main: engineer, operator, admin. Их BCrypt-хэши находятся в init.sql; открытые пароли автор этой ветки не получал и не менял. Используйте пароли коллеги, который делал авторизацию. Старый пароль отдельного демо из KOLYA здесь не гарантируется.

Стандартные порты: БД 3306, API 8080, PHP-сайт 5092. При занятости порта измените соответствующий DB_PORT/API_PORT/SITE_PORT в .env.

## Если остались контейнеры прежней версии

Посмотрите контейнеры:

```powershell
docker ps -a
```

Если именно `motiv_api_container` и `motiv_mariadb_container` принадлежат прежнему запуску этого проекта, остановите и удалите только их:

```powershell
docker rm -f motiv_api_container motiv_mariadb_container
```

Команда не удаляет Docker-тома. Данные старой MariaDB 11 нельзя подключать к MariaDB 10.1. Новая конфигурация использует другой том `motiv_report_main_aff0a9f`; старые данные остаются отдельно. При необходимости данных сначала сделайте дамп старой БД. Во время разработки этой ветки дампы активных прежних БД были сохранены локально; они не входят в GitHub.

Старое отдельное демо карты `motiv-monitoring-demo-monitoring-1` может занимать 5092. Если это ваш прошлый демо-контейнер, остановите его или выберите другой SITE_PORT. Не удаляйте все контейнеры Docker: на компьютере могут работать другие проекты.

## Запустить

Из корня используйте **явно указанный compose-файл**:

```powershell
docker compose --env-file .env -f docker-compose.yml up -d --build
```

Явное `-f docker-compose.yml` не подключает старый Visual Studio override с дополнительными HTTPS-портами и сертификатами. При первом запуске нужны интернет для образов/зависимостей и время на инициализацию SQL. API ждёт создания всех трёх процедур БД.

Открыть:

- PHP-сайт: http://127.0.0.1:5092/
- Swagger API: http://127.0.0.1:8080/swagger
- Health: http://127.0.0.1:8080/api/health

Если порты изменены в .env, подставьте свои. Внутри Docker PHP всегда использует alias `api:8080`, ему не нужен внешний API_PORT.

```powershell
docker compose --env-file .env -f docker-compose.yml ps
docker compose --env-file .env -f docker-compose.yml logs --tail 50 motiv-db
docker compose --env-file .env -f docker-compose.yml logs --tail 50 motivcellscopeapiservices
docker compose --env-file .env -f docker-compose.yml logs --tail 50 php-site
```

База должна стать healthy, API — отвечать `status=ok`, сайт — показывать форму входа. Если пароль не подходит, это отдельный вопрос к созданным в main пользователям, а не к паролю MariaDB.

## Проверить сценарий

1. Войти существующим operator. Открыть дашборд, журнал, отчёты и мониторинг.
2. Создать тестовый инцидент; выбрать справочники либо оставить неизвестные поля пустыми. Начало/окончание вводятся в UTC.
3. Для трёх БС и перерыва 00:20:00 общий простой должен быть 01:00:00. Для сектора или неизвестного числа БС он неизвестен, а не нулевой.
4. Изменить комментарий, сохранить. При конфликте версии форма должна сохранить ввод и показать ошибку.
5. Ограничить период/поиск, скачать детальный и групповой CSV.
6. Войти engineer: просмотр и CSV доступны, правка запрещена также самим API.
7. В мониторинге видны реальные KPI/аномалии из новой БД. Доступность может быть неизвестна; активность трафика подписана отдельно. Карта пока является заглушкой.

## Остановка и обновление

```powershell
docker compose --env-file .env -f docker-compose.yml down
git pull --ff-only origin kolya-api-sync
docker compose --env-file .env -f docker-compose.yml up -d --build
```

Обычный down сохраняет том новой БД. Сброс данных не является частью обычного обновления. init.sql исполняется при первой инициализации пустого тома; повторный up не заменяет существующую схему.

## Изменение PHP без .NET

Все файлы — в php-site/. Изменив их, пересоберите только сайт:

```powershell
docker compose --env-file .env -f docker-compose.yml up -d --build --no-deps php-site
```

С установленным PHP 8.4 и cURL можно работать из папки php-site без пересборки:

```powershell
$env:API_BASE_URL='http://127.0.0.1:8080'
php -S 127.0.0.1:5092 -t .
```

Предварительно освободите порт 5092, остановив только контейнер сайта. Сам API и БД должны продолжать работать. Python HTTP server не выполняет PHP, поэтому для этого сайта он не подходит.
