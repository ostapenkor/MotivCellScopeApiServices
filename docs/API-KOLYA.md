# API в ветке KOLYA

Пять методов требуют `Authorization: Bearer <JWT>`:

| Метод | Параметры |
| --- | --- |
| GET /api/vendors | Без параметров; vendorId, code, name, ratSupported |
| GET /api/dashboard/summary | Обязательные from, to; необязательный regionId |
| GET /api/incidents | Обязательные from, to; regionId, category, severity, page (1), pageSize (50, максимум 200) |
| GET /api/bts | regionId; необязательная пара from, to |
| GET /api/reports/export | Обязательные from, to; regionId; format=csv |

Даты передаются в ISO 8601, предпочтительно с `Z` или явным смещением, и переводятся в UTC. Период — `[from, to)`. Аномалии и инциденты выбираются по пересечению с периодом, включая начавшиеся раньше и ещё не завершённые события.

CSSR = 100 × сумма успешных соединений / сумма попыток. DCR = 100 × сумма обрывов / сумма успешных соединений. При нулевом знаменателе возвращается null. Трафик в десятичных GB (10^9 байт). Доступность соответствует формуле SQL проекта: доля имеющихся почасовых KPI-записей с попытками или трафиком. Отсутствующие записи не считаются нулевой доступностью; полное отсутствие KPI даёт null.

Дашборд: btsActive — active, btsProblem — degraded/down. Счётчики БС и сот отражают текущее состояние сети; KPI и аномалии — выбранный период. anomaliesOpen и anomaliesCritical учитывают new/acknowledged, anomaliesExplained — explained.

Карта учитывает new/acknowledged/explained; resolved/false_positive не окрашивают БС. При нескольких аномалиях выбирается максимальная severity, затем самая поздняя tsFrom, затем максимальный ID. kpiCode и incidentId относятся к одной выбранной аномалии. Если период не передан, учитывается вся история этих статусов. В текущей схеме нет технологии соты: параметр technology возвращает 400 unsupported_filter; справочник производителей не позволяет достоверно определить технологию каждой соты.

Инциденты сортируются по startedAt DESC, incidentId DESC. durationMin — фактическая продолжительность (для открытых — до текущего UTC), не обрезанная периодом фильтра. btsCode может быть null для регионального инцидента.

CSV содержит все соты выбранного региона, включая соты без измерений; отсутствующие KPI — пустые поля. Количество аномалий включает все пересекающие период статусы, кроме false_positive. UTF-8 BOM, CRLF, десятичная точка, кавычки и защита текстовых полей от формул Excel.

## init.sql

Схема таблиц, представления, исходные справочники и пороги сохранены. Удалены повторные вставки справочников и блоки для отсутствующих таблиц старой схемы. Убраны commissioned_at/link_id и хендоверные KPI, отсутствующие в текущей схеме. PM-генератор использует пять метрик текущего каталога. После создания трёх процедур выполняются первоначальные расчёты KPI и аномалий.

На чистой базе: 4 региона, 3 вендора, 20 БС, 60 сот, 3 инцидента, 57 575 PM-строк и 11 515 KPI-строк. Все три процедуры создаются и выполняются.

Скрипт предназначен для новой пустой базы. MariaDB не повторяет `/docker-entrypoint-initdb.d` для существующего тома. Исправление файла само по себе не обновляет существующую базу. Не запускайте полный скрипт поверх заполненной БД; для неё нужна отдельная миграция. Рабочая база при разработке и проверках не изменялась.

## Проверки

Интеграционный исполняемый проект `tests/ApiChecks` использует настоящую MariaDB, временные базы со случайными именами и отдельный HTTP-сервер на 127.0.0.1:51879. Тестовый пользователь БД должен иметь права CREATE/DROP DATABASE. Пароль не хранится в репозитории.

Из корня репозитория в PowerShell, задав API_CHECK_CONNECTION локально:

```powershell
$env:API_CHECK_INIT = (Resolve-Path ./init.sql).Path
dotnet run --project ./tests/ApiChecks/ApiChecks.csproj -p:UseAppHost=false
```

Проверяются полный SQL, создание и вызов процедур, стабильное количество аномалий при повторном расчёте, JWT для пяти маршрутов, формулы, границы периода, фильтры, пагинация, CSV, отсутствие данных и неверные параметры. Временные базы удаляются в finally. Проверки не вызывают административные методы рабочей базы.
