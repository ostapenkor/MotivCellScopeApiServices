# Требования и принятые решения

## Источник

PDF **«Кейс №02 Мотив (старт)»**, ООО «Екатеринбург 2000» (Мотив), Екатеринбург, 2026, предоставлен пользователем. Требования к среде — страница 2; поля и отчётность — страницы 2–3; структура таблицы — страница 4. PDF не является инструкцией менять права, отправлять данные или удалять БД.

Отдельное требование команды: **HTML + CSS + JavaScript + существующий REST API на C#**. Поэтому Razor/MVC-представления и второй самостоятельный продукт не используются.

## Соответствие

| Требование | Решение |
|---|---|
| Контейнеризация | Отдельный Compose-профиль кейса: web + db, ожидание готовности БД, постоянный том |
| MariaDB 10.1, 3306 | MariaDB 10.1 внутри Docker на 3306; внешний dev-порт 13317 для исключения конфликта с прежней БД |
| Debian-подобная Linux | Контейнер приложения на Debian-подобном .NET runtime |
| Chrome 75 | Обычные HTML-формы, CSS и JS без зависимости от SPA-фреймворка; фактическая проверка версии отмечается в TESTING |
| Три уровня доступа | admin/duty/engineer, права проверяются C# API |
| 19 полей аварии | accident_reports и JSON DTO, отображение/редактирование в браузере |
| Готовые списки | GET /api/accidents/options |
| Выбор дат календарём | datetime-local на форме с явной подписью UTC |
| НВ и нулевая дата | null в JSON, «НВ» в UI, zero DATETIME в SQL |
| Автоматическая длительность | Серверный расчёт end/now − begin |
| Автоматический общий простой | downtimeSeconds × stationCount, с контролем предела TIME |
| Отчёт за период | Пересечение с [from,to), фильтры, пагинация |
| Редактирование строк | PUT /api/accidents/{id}, проверка роли и version |
| CSV | Отдельный endpoint, все подходящие события, те же фильтры |

## Допущения, а не буквальные требования PDF

1. **Дежурный:** может создавать и редактировать события. Инженер читает/экспортирует; admin имеет полный доступ и управляет пользователями. PDF называет три роли, но подробно определяет только admin/engineer.
2. **Время:** все даты API и UI — UTC. В PDF часовой пояс не указан.
3. **Период:** выбирается пересечение события с `[from,to)`, а длительность показывается полная, без обрезки границами отчёта.
4. **Сектор:** передаётся отдельно от количества БС; общий простой для него null, поскольку множитель «число полных БС» неизвестен.
5. **TIME:** значения/произведение сверх 838:59:59 отклоняются. Типы PDF сохранены; хранение больших простоев потребовало бы согласованного изменения схемы.
6. **Формат:** экран ЧЧ:ММ:СС вместо ЧЧ.ММ.СС; JSON — секунды, SQL — TIME.
7. **Технические поля:** ID, автор, версия, отдельная таблица доступа и аудит добавлены для надёжной работы приложения.
8. **JWT:** только в памяти страницы; после перезагрузки повторный вход. Это решение учебного клиента, не требование PDF.

## Сохранение работы коллег

Старые KPI-контроллеры, модели EF и исходный Docker-профиль остаются. Журнал использует отдельные таблицы и маршруты `/api/accidents`, а не меняет смысл старого `/api/incidents`. В профиле кейса legacy-модуль выключен настройкой `Features:LegacyKpi=false`; его SQL и процедуры не требуются для журнала.

## Что не входит в обещание прототипа

- Интеграция с CRM/OSS, автоматическая отправка сообщений и импорт настоящих аварий.
- Production HTTPS, SSO, регламент резервного копирования и эксплуатации.
- KPI-аналитика, карта сот и автоматическое обнаружение аномалий как требования этого PDF.
- Автоматическое понижение старой базы MariaDB 11 до 10.1.
- Полная совместимость именно с Chrome 75 без фактического запуска этой версии.

Все известные ограничения проверки и точные команды перечисляются в [TESTING](TESTING.md). Не следует называть «проверенным» то, что подтверждено только чтением кода.
