# Как устроен код: от кнопки до SQL

## Общая схема

```text
index.html + styles.css
        ↓ действия пользователя
app.js: fetch('/api/accidents', ...)
        ↓ JSON + Authorization
AccidentsController
        ↓ проверка прав и полей
AccidentStore
        ↓ параметризованный SQL
MariaDB 10.1
```

Ответ возвращается обратно как JSON. JavaScript обновляет таблицу и сообщения. В C# нет Razor-представлений этого интерфейса: браузер получает HTML как статический файл, а данные — отдельно из REST API.

## Пять терминов

- **HTML** — какие элементы находятся на странице: форма, кнопка, таблица.
- **CSS** — как они выглядят и размещаются на разных экранах.
- **JavaScript** — что происходит при нажатии кнопки и как данные появляются на странице.
- **REST API** — адреса и HTTP-методы, через которые клиент читает/меняет данные.
- **JSON** — текстовое представление объекта: `{"category":1,"endTime":null}`.

`GET` читает, `POST` создаёт, `PUT` обновляет, `DELETE` удаляет. Сама надпись кнопки прав не даёт — сервер проверяет пользователя для каждого защищённого запроса.

## Что читать по порядку

1. `wwwroot/index.html`: найдите поля начала аварии, количества БС и кнопку сохранения.
2. `wwwroot/app.js`: найдите обработчик сохранения и общий код обращения к `/api/...`.
3. `Contracts/Accidents.cs`: посмотрите, какие поля JSON разрешено прислать и какие проверки выполняются.
4. `Controllers/AccidentsController.cs`: найдите POST и PUT — они связывают запрос, права и хранилище.
5. `Data/AccidentStore.cs`: найдите INSERT/UPDATE и соответствующие SQL-параметры.
6. `db/journal.sql`: сопоставьте свойства DTO со столбцами, пользуясь [таблицей соответствия](DATABASE.md).
7. `Program.cs`: посмотрите регистрацию зависимостей, JWT, статических файлов и отключение старого KPI-модуля в профиле кейса.
8. `Services/JournalBootstrap.cs`: начальная настройка пользователей и демо-данных без перезаписи существующих записей.

## Путь кнопки «Сохранить»

1. JS читает значения HTML-полей.
2. Время ЧЧ:ММ:СС преобразуется в целое количество секунд; календарные даты отправляются в UTC.
3. Создаётся объект JSON. Длительность, общий простой, автор и роль в него не подставляются как доверенные значения.
4. `fetch` отправляет POST/PUT с Content-Type application/json и JWT в Authorization.
5. C# проверяет токен и права. Затем проверяет значения DTO.
6. Хранилище выполняет SQL с параметрами. При изменении проверяется `version`.
7. Сервер сохраняет запись и аудит, возвращает результат или ошибку.
8. JS показывает успех и перечитывает журнал. При ошибке введённый текст остаётся в форме.

## Почему параметры SQL обязательны

```csharp
command.Parameters.AddWithValue("@description", request.Description);
```

Описание передаётся базе **как значение**, а не как кусок SQL. Пользовательский текст с кавычками не должен менять смысл команды. Нельзя писать SQL через склейку `"... WHERE username='" + username + "'"`.

`using` закрывает соединение/запрос даже при ошибке. `async` и `await` позволяют серверу не занимать рабочий поток, пока база отвечает. **DI** означает, что ASP.NET создаёт AccidentStore и передаёт его контроллеру; контроллер не ищет пароль БД и не открывает соединение вручную.

## DTO, таблица и экран — разные вещи

DTO — контракт JSON. Таблица — формат хранения. Экран — удобное представление для человека. Поэтому в таблице `AKB TIME`, в API `batterySeconds:5400`, а на экране `01:30:00`. Так же zero DATETIME в БД преобразуется в null API и надпись «НВ».

Это небольшое разделение помогает не отдавать пароль/служебные свойства и не привязывать HTML к опечаткам SQL-полей `TEHC`/`LENGHT`.

## Даты и арифметика

Все даты API — UTC. Длительность считается на сервере, а не принимается от JS. Для незавершённой аварии сервер берёт текущее время. UI может продолжать показывать счётчик от `serverTimeUtc`, но при сохранении и экспорте расчёт выполняется заново.

Общий простой — простой одной БС × количество. Для сектора количество полных БС неизвестно, поэтому значение null. Нельзя незаметно заменить null на 0: нулевой простой и неизвестный простой — разные факты.

## Безопасность и роли простыми словами

- JWT подтверждает вход, но права определяет сервер. Роль нельзя получить заменой HTML или поля JSON.
- Токен живёт в памяти страницы; обновление страницы приводит к повторному входу.
- Пользовательский текст вставляется как текст, а не исполняемый HTML.
- CSV защищён от превращения описания в формулу Excel.
- Версия записи защищает от потери правок коллеги.
- `.env.case` содержит локальные секреты и не включается в Git.

## Как расширить форму

Сначала согласовать изменение с заданием и командой. Затем обновить схему/миграцию, входной DTO и его валидацию, чтение/запись SQL, ответ API, HTML/JS, CSV, тесты и документацию. Один новый `<input>` сам по себе не создаёт столбец БД.

Для учебного проекта не требуются отдельный React-сервер, AutoMapper, CQRS или набор абстрактных репозиториев. Используем прямой и прослеживаемый путь: HTML → JS → контроллер → SQL.
