## Что покрывают 139 проверок

- Реальный login трёх ролей и auth/me; неверный пароль и анонимный доступ.
- Серверный запрет инженеру создавать/изменять, дежурному удалять/управлять пользователями.
- Все поля записи после создания и чтения; автор и версия задаются сервером, вычисляемые поля клиента игнорируются.
- НВ: JSON null → zero DATETIME → JSON null. Сектор: nullable stationCount + isSector → NUMB_RBS=-1, общий простой null.
- Формулы, неверные списки, количество, отрицательные/дробные секунды, предел TIME, длинный текст, неверные даты, JSON-дата числом/объектом.
- 409 для устаревших PUT и DELETE, 404 для отсутствующей записи; конфликт не перезаписывает сохранённые данные.
- Пересечение периода [from,to), обе касающиеся границы, статус и пагинация 27 записей на страницы 25+2 без дублей.
- CSV содержит ID + 19 полей, все строки фильтра, те же критерии, что JSON-таблица.
- Создание пользователя, смена роли, немедленный отзыв старого JWT, отключение и отказ во входе, запрет отключать/понижать текущего администратора.
- Аудит доступен администратору, остальные роли не получают его.

Тесты находятся в `tests/CaseChecks/smoke.py`. Только Python 3 standard library. Обязательна переменная ALLOW_CASE_TEST_WRITES=1 и loopback-адрес. Каждый прогон удаляет только свои события по полученным ID и уникальному маркеру; временного пользователя отключает. История тестовых действий в аудите намеренно остаётся.

```powershell
$env:ALLOW_CASE_TEST_WRITES = '1'
$env:CASE_BASE_URL = 'http://127.0.0.1:5090'
$env:DEMO_PASSWORD = 'ваш пароль из .env.case'
python tests/CaseChecks/smoke.py
```

## Docker и сеть при проверке

На проверяющем компьютере системный DNS временно не разрешал NuGet/Microsoft registry. Официальные пакеты и образы скачаны с сохранённой TLS-проверкой; SHA256 manifests/config/layers проверены. Для сборки неизменного Dockerfile использованы локальные OCI named build contexts и кэш официальных NuGet-пакетов. Системные и Docker DNS-настройки не изменялись. Сама Linux-сборка C# и публикация выполнялись внутри SDK-контейнера; это не замена готовой DLL в образе.

При обычной доступной сети коллегам достаточно команды Compose из README. Проверка не доказывает первый запуск на полностью отключённой от интернета машине.

## Найденная и исправленная ошибка перезапуска

`docker compose restart` не ждёт healthcheck зависимостей. API первоначально мог завершиться, если MariaDB ещё стартовала. Bootstrap теперь ограниченно повторяет только ошибки подключения; ошибки SQL и пароля не скрываются. Повторный одновременный restart после исправления прошёл, данные сохранились.

## Границы проверки

Не выполнялись нагрузочное испытание, проверка конкретного старого Chrome 75, production HTTPS, резервное восстановление и развёртывание в инфраструктуре заказчика. Прототип привязан к localhost. Длительности TIME ограничены форматом PDF, это явно валидируется; статистика не подменяется выдуманными KPI.
