# REST API журнала

Базовый адрес — тот же, что у интерфейса: `http://localhost:5090`. JavaScript использует относительные URL `/api/...`; отдельный CORS-прокси не нужен. Вход возвращает JWT, который передаётся заголовком:

```http
Authorization: Bearer <token>
```

Токен хранится в памяти JS. Пароль не сохраняется. При 401 клиент очищает состояние входа и предлагает войти снова. 403 означает, что пользователь вошёл, но действие его роли запрещено.

## Вход

`POST /api/auth/login`, без JWT:

```json
{"username":"duty","password":"пароль из настройки DemoPassword"}
```

Успешный ответ содержит `token`, `expiresAt`, `username`, `userId`, `role`. Значение токена нельзя копировать в документацию/логи/URL. `GET /api/auth/me` проверяет текущий вход и возвращает сведения о пользователе. Само имя `admin` не является доказательством прав: роль проверяется сервером.

## Справочники и права

`GET /api/accidents/options`, требуется вход. Поля:

- `directions`: ХМЯН, СВН, ЮЗН, Вся сеть.
- `centers`: НБР, АСБ, ИРБ, КРТ, НТГ, НТР, НУРЛ, НВРТ, НУРГ, ОКТ, СЛХ, СОВ, СРГ, ХМН, ЕКБ, КМУ, КРГ, НСР.
- `networkTypes`: GSM, LTE, LTE/GSM.
- `alarmTypes`: РРС, ССС, ЭЛ, RBS, МСПД, ТМ, ОПС, ПР, АВР, Аренда.
- `serverTimeUtc`: текущее время сервера.
- `permissions`: `canWrite`, `canDelete`, `canManageUsers`.

UI строит списки из ответа и скрывает недоступные действия. API независимо проверяет те же права: ручной запрос не обходит ограничения.

## Список и сводка

```http
GET /api/accidents?from=2026-11-01T00:00:00Z&to=2026-11-14T00:00:00Z&page=1&pageSize=25
```

| Параметр | Назначение |
|---|---|
| from, to | Начало и конец UTC, `from < to` |
| direction | Направление из options |
| center | ТЦ из options |
| category | 1, 2, 3 |
| networkType | GSM, LTE, LTE/GSM |
| status | all, open, closed |
| search | Поисковый текст |
| page, pageSize | Страница и размер, положительные числа в пределах серверной валидации |

Период `[from,to)`, событие должно пересекать его. Ответ:

```json
{
  "total": 3,
  "page": 1,
  "pageSize": 25,
  "serverTimeUtc": "2026-11-13T12:00:00Z",
  "summary": {"total":3,"open":2,"closed":1,"categoryOne":1},
  "items": []
}
```

`items` содержит карточки событий. Счётчики относятся к выбранным фильтрам и всему результату, а не только к одной странице.

## Создание и изменение

- `GET /api/accidents/{id}` — получить карточку, любой пользователь журнала.
- `POST /api/accidents` — создать, admin/duty. Ответ 201 с адресом созданной записи.
- `PUT /api/accidents/{id}` — заменить редактируемые поля, admin/duty; требуется актуальная `version`.
- `DELETE /api/accidents/{id}?version=...` — удалить, только admin; требуется актуальная версия.

Пример тела создания:

```json
{
  "pw": "https://crm.example/ntt/123",
  "direction": "СВН",
  "center": "ЕКБ",
  "category": 1,
  "networkType": "LTE",
  "serviceElement": "БС ЕКБ-001, ул. Малышева, 51",
  "stationCount": 3,
  "isSector": false,
  "equipment": "Описание оборудования",
  "alarmType": "ЭЛ",
  "description": "Отключение основного питания",
  "beginTime": "2026-11-13T08:00:00Z",
  "endTime": null,
  "batterySeconds": 5400,
  "generatorSeconds": 7200,
  "downtimeSeconds": 1200,
  "notified": "Дежурный инженер, электросетевая организация",
  "notes": "Питание от генератора"
}
```

Для обновления добавляется `version` из последнего GET. `id` берётся из URL. Автор, роль и вычисленные значения не задаются клиентом.

Правила:

- `stationCount` — целое количество БС; для сектора `isSector:true`, `stationCount:null`.
- `endTime:null` означает НВ. Чтобы закрыть событие, передать дату окончания.
- Даты — ISO 8601 UTC с `Z`; окончание не раньше начала.
- `batterySeconds`, `generatorSeconds`, `downtimeSeconds` — целые неотрицательные секунды, не строки `"01:00:00"` и не даты.
- Текстовые поля соответствуют ограничениям VARCHAR(450); значения списков проверяются сервером.
- Произведение простоя и количества должно помещаться в SQL TIME; для сектора оно не определено.

В ответе к редактируемым полям добавляются `id`, `createdBy`, `createdByName`, `version`, `durationSeconds`, `totalDowntimeSeconds`, `serverTimeUtc`. Два вычисленных поля — это длительность и общий простой из PDF. Для НВ фронтенд может показывать тикающий счётчик, используя серверное время как опорную точку.

### Одновременные изменения

Два пользователя получили version=4. Первый сохранил — версия стала 5. Второй отправляет version=4 и получает **409 Conflict**. Он должен перечитать запись и согласовать правки; автоматическая повторная отправка с новой версией потеряла бы изменения коллеги.

## CSV и аудит

`GET /api/accidents/export.csv` принимает те же содержательные фильтры, что список. Пагинация не ограничивает экспорт: выгружаются все соответствующие события и все 19 полей. Ответ — файл CSV, не JSON. Клиент отправляет JWT, получает Blob и предлагает скачать файл; токен не вставляется в ссылку.

CSV экранирует кавычки, переносы строк и потенциальные формулы электронных таблиц. Даты явно подписаны UTC. Если Excel открыл одну колонку, используйте импорт текста/CSV с разделителем из заголовка файла и кодировкой UTF-8.

`GET /api/accidents/audit?page=1&pageSize=25` — просмотр журнала действий администратором. Аудит показывает автора, событие, действие и время. Полные старые версии текста он не заменяет.

Ответ аудита: `total`, `page`, `pageSize`, `items`. Элемент items содержит `id`, `accidentId`, `username`, `action`, `occurredAt`.

## Пользователи

Только admin:

- `GET /api/users` — просмотреть учётные записи и доступ к журналу.
- `POST /api/users` — создать пользователя с начальным паролем и ролью.
- `PUT /api/users/{id}/access` — изменить `role`, `active`, `version`.

GET возвращает массив объектов `userId`, `username`, `role`, `active`, `version`. Тело создания: `username`, `password`, `role`; успешное создание — 201. Тело изменения доступа: `role`, `active`, актуальная `version`.

Роли: `admin`, `duty`, `engineer`. Нельзя доверять роли, присланной при обычном входе или в форме аварии. Сервер читает доступ из `journal_user_access`. Пароли/хеши не возвращаются списком пользователей. Разделение входа и доступа позволяет сохранить прежнюю структуру `users`.

## Ошибки

| Статус | Значение для клиента |
|---|---|
| 400 | Неверные поля, период, списки или переполнение времени; показать ошибки формы |
| 401 | Вход отсутствует/истёк; повторно войти |
| 403 | Недостаточно прав; не повторять тот же запрос |
| 404 | Запись не найдена |
| 409 | Конфликт версий/уникальности; перечитать данные и согласовать |
| 500 | Неожиданная серверная ошибка; сохранить ввод, сообщить traceId при наличии |

Ошибки описываются JSON ProblemDetails. Для валидации поле `errors` содержит массив сообщений по именам полей. Клиент не должен пытаться читать успешную карточку из ответа с ошибкой. SQL, пароли и трассировки исключений не должны показываться пользователю.
