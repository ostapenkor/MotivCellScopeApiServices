# Результат пересмотра проекта

Основной источник требований — окончательный PDF кейса и уточнение коллеги: HTML + CSS + JS + существующий C# REST API. Прежний KPI-проект был тренировкой. Этот коммит не выдаёт его методы за реализацию журнала аварий.

## Исправлено

1. Razor/MVC-прототип заменён статическими страницами в wwwroot; браузер реально вызывает JSON API. Старый отдельный прототип не добавлен в репозиторий.
2. Добавлен модуль accident_reports для 19 полей, не смешанный с тренировочным incidents. Входные DTO отделены от авторства и вычисляемых значений.
3. Роли проверяются сервером, не только кнопками. Изменение роли/active/version отзывает прежний JWT. Тренировочная админка ограничена admin.
4. Добавлены транзакционный аудит, защита версий, 409 на конфликт и 400 на неверные даты/JSON вместо 500.
5. Инициализация демо атомарна и не перезаписывает существующие пароли/права; добавлено ожидание БД при restart.
6. Для MariaDB 10.1 создан отдельный совместимый SQL без CTE/оконных функций. Схема старого KPI-модуля сохранена отдельно; старый том не используется.
7. Удалён устаревший вложенный init.sql. Для тренировки канонический файл — корневой init.sql; для кейса — db/journal.sql. Пути явно указаны в Compose.
8. Убраны пароли из отслеживаемого шаблона VS; .env.case исключён из Git и Docker context. Старую историю Git не переписывали.
9. Строка подключения создаётся builder-ом, работает стандартная конфигурация JWT вне secrets; запуск не требует AutoDetect-соединения к ещё не готовой БД.
10. Убраны пустые тестовые операции Regions и неиспользуемые SQLite-зависимости. MySqlConnector явно обновлён до 2.6.2. Docker images закреплены на Debian bookworm.

## Осознанно сохранено

Тренировочные KPI-контроллеры и модели не удалены, чтобы не потерять работу коллег. В профиле кейса они не регистрируются. Старый AdminController и его алгоритмы пересчёта остаются тренировочными и не входят в приёмку PDF. Их дальнейшая доработка не нужна для текущего журнала.

## Решения, требующие согласования с заказчиком

UTC, права дежурного, маркер сектора -1, NULL общего простоя сектора, предел TIME и правило пересечения периода перечислены в REQUIREMENTS.md. Не считать эти допущения дословными указаниями PDF. Проверка Chrome 75 конкретной версии остаётся отдельной задачей.
