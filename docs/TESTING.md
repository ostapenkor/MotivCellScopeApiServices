# Проверки ветки kolya-api-sync

На реальном локальном стеке MariaDB 10.1.48 + C# .NET 8 + PHP 8.4 выполнены:

- 99 HTTP-проверок API — успешно. Реальный вход через существующую авторизацию, роли, CRUD, все поля, TIME больше суток, null/сектор/ноль, контроль версии, CSV, фильтры, справочники, старые URL, KPI, скрытые координаты. По одному разу выполнены новые обёртки refresh-kpi и detect-anomalies.
- 131 HTTP-проверка цепочки браузероподобный клиент → PHP → cURL → API — успешно. Все вкладки, cookie-сессия, отсутствие JWT в HTML/JS, CRUD, сохранение ввода при 409, CSV, CSRF 403, права инженера и выход.
- PHP lint: index.php и ApiClient.php без синтаксических ошибок. JS используется только локально для интерфейса.
- Docker Release build API: 0 предупреждений, 0 ошибок.
- В браузере проверены вход и дашборд, сохранён снимок; ошибок консоли не найдено.
- Новая БД создалась с 20 исходными инцидентами, 11515 KPI-строками, 38 аномалиями и тремя процедурами. Пересчёт может менять количество производных записей; это не фиксированная проверка на каждое будущее состояние.
- Изменения AuthController/AdminController относительно main aff0a9f отсутствуют. Приложения не используют async/await/Task для своих операций; нет блокировок через .Result/.Wait.

Созданные тестами инциденты удалены. Аудит сохранён. Временные учётные записи предназначены только для локального прогона и удаляются после проверки. Учётные записи коллеги и их пароли не менялись. Старые Docker-тома сохранены; резервные дампы находятся вне репозитория.

## Повторить проверки

Нужны Python 3 и локальная учебная БД с двумя заранее созданными тестовыми учётными записями operator/engineer. У обеих должен быть известный тестовый пароль. Тесты не создают пользователей и не подделывают JWT — пароли проверяет существующий AuthController.

```powershell
$env:TEST_OPERATOR='имя_тестового_оператора'
$env:TEST_ENGINEER='имя_тестового_инженера'
$env:TEST_PASSWORD=Read-Host 'Пароль тестовых учётных записей'
$env:ALLOW_TEST_WRITES='1'
python tests/api_smoke.py
python tests/php_flow.py
Remove-Item Env:TEST_PASSWORD
Remove-Item Env:ALLOW_TEST_WRITES
```

По умолчанию API — 127.0.0.1:8080, сайт — 127.0.0.1:5092. Можно передать TEST_BASE_URL/TEST_SITE_URL. Запись разрешена только при ALLOW_TEST_WRITES=1 и адресах loopback. Тесты удаляют только свои записи с уникальным маркером; аудит остаётся.

`RUN_MAINTENANCE_TESTS=1` включает ещё два вызова процедур через новые маршруты мониторинга. Они пересчитывают общие KPI/аномалии учебной БД; для обычной проверки CRUD этот флаг не нужен. Скрипты не вызывают /api/admin. В открытый репозиторий не помещаются тестовые пароли, JWT, .env, дампы и исходный Excel.

Полный повтор проверки старой ветки KOLYA не проводился: это другая схема и другая ветка. Точный Chrome75 не установлен; текущий браузерный результат не выдаётся за проверку всех старых версий браузера.
