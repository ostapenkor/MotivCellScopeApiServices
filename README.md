# МОТИВ: журнал аварий — HTML, CSS, JavaScript + C# REST API

Учебный прототип по PDF «Кейс №02 Мотив (старт)». Пользователь вводит сведения об аварии, получает отчёт за период и скачивает CSV. Интерфейс находится в `wwwroot`: это обычные HTML/CSS/JS, **без Razor, React и отдельного сервера фронтенда**. JavaScript отправляет JSON-запросы к C# `/api/...`, а C# читает и сохраняет данные в MariaDB.

Прежний модуль KPI был тренировкой до выдачи окончательного задания. Он сохранён для истории и совместимости, но не определяет требования кейса. В профиле кейса `Features:LegacyKpi=false`: старые маршруты не активируются и SQL прежнего модуля не запускается.

## Быстрый запуск кейса

Нужен Docker с Linux containers и Docker Compose. Команды выполняются **из корня репозитория**.

1. Скопируйте `.env.case.example` в `.env.case`.
2. Откройте `.env.case` и задайте отдельные пароли БД, пароль демо-пользователей и случайный ключ JWT. Не оставляйте пример/заглушку. `.env.case` не должен попадать в Git.
3. Запустите:

```sh
docker compose --env-file .env.case -f docker-compose.case.yml -p motiv-case up -d --build
```

Откройте **http://localhost:5090**. Если включён `AccidentJournal:SeedDemo`, при первом запуске создаются `admin`, `duty`, `engineer`; пароль берётся из `DemoPassword` в конфигурации. Существующие учётные записи и их пароли не перезаписываются.

В примере `.env.case.example` база публикуется на `127.0.0.1:3306`, как в задании. Если порт занят тренировочной базой, задайте `CASE_DB_PORT=13317` в своём `.env.case` (именно так настроен текущий локальный стенд). Внутри Docker MariaDB слушает **3306**, как требует кейс. Версия БД — **MariaDB 10.1**.

Статус, журнал и безопасная остановка:

```sh
docker compose --env-file .env.case -f docker-compose.case.yml -p motiv-case ps
docker compose --env-file .env.case -f docker-compose.case.yml -p motiv-case logs --tail=100
docker compose --env-file .env.case -f docker-compose.case.yml -p motiv-case stop
docker compose --env-file .env.case -f docker-compose.case.yml -p motiv-case start
```

`stop` сохраняет том и данные. **Не используйте `down -v` для сохранённого журнала:** это удаляет том. Не направляйте профиль кейса на том MariaDB 11 прежнего проекта и не применяйте старый `init.sql` к MariaDB 10.1.

## Что умеет приложение

- Вход, три роли и проверка прав на стороне C#.
- Форма со всеми 19 полями кейса, списками и календарём.
- НВ для незавершённой аварии; автоматические длительность и общий простой.
- Журнал, карточка события, редактирование и защита параллельных правок.
- Фильтры, страницы, сводные счётчики и CSV за весь выбранный период.
- Административное управление доступом пользователей и журнал действий.

Токен входа хранится только в памяти страницы. При обновлении/закрытии страницы нужно войти снова. Это сознательное упрощение учебного прототипа: пароль и JWT не сохраняются в `localStorage`.

```text
MotivCellScopeApiServices/
  Program.cs                         настройка приложения и DI
  Contracts/Accidents.cs             JSON-модели, списки и проверки

```

## Границы прототипа

Это локальный учебный стенд. Перед общей эксплуатацией нужно настроить HTTPS, резервные копии, политику паролей и согласовать неоднозначности PDF (время, права дежурного, сектор, предел TIME). Совместимый синтаксис JavaScript не является подтверждением испытаний именно на Chrome 75: фактический результат проверок указан отдельно.

## Настройки локального кейса

| Переменная .env.case | Назначение |
|---|---|
| CASE_DB_PASSWORD | Пароль пользователя motiv для отдельной базы |
| CASE_DB_ROOT_PASSWORD | Отдельный пароль root MariaDB |
| CASE_JWT_KEY | Случайный ключ JWT, минимум 32 байта |
| DEMO_PASSWORD | Начальный пароль admin/duty/engineer; минимум 8 символов, максимум 72 байта UTF-8 |
| CASE_DB_PORT | Порт БД на компьютере: 3306, либо 13317 при конфликте |
| CASE_WEB_PORT | Порт интерфейса: по умолчанию 5090 |

Существующие учётные записи не меняются при редактировании DEMO_PASSWORD. Для создания обычного пользователя используйте вкладку «Пользователи» под администратором. Встроенного сброса пароля в прототипе нет.

Проверка реального REST-хоста (Python 3, без сторонних библиотек):

```powershell
$env:ALLOW_CASE_TEST_WRITES = '1'
$env:CASE_BASE_URL = 'http://127.0.0.1:5090'
$env:DEMO_PASSWORD = 'ваш пароль из .env.case'
python tests/CaseChecks/smoke.py
```

Тест предназначен только для отдельного учебного стенда: он создаёт собственные события и пользователя, удаляет только свои события, отключает созданного пользователя; аудит остаётся. Нельзя запускать его на рабочей базе.
