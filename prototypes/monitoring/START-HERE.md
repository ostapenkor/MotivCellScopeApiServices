# Как запустить мониторинг у себя

Это инструкция именно к макету мониторинга из HTML лиды. Здесь уже работают карта четырёх регионов, гексагоны, фильтры, поиск, масштабирование и карточка со списком БС. Станции и аномалии вымышленные. Остальные вкладки сохраняют поведение исходного макета, настоящий C# REST к этой вкладке ещё не подключён.

Репозиторий: https://github.com/ostapenkor/MotivCellScopeApiServices

**Нужна ветка `KOLYA`, папка `prototypes/monitoring`.** В `main` эта версия автоматически не появляется. Если GitHub показывает 404, проверьте вход в аккаунт и доступ к репозиторию у владельца `ostapenkor`.

## 1. Скачать код

Откройте PowerShell или терминал. Для первого запуска удобнее сделать отдельную новую копию:

```powershell
git clone --branch KOLYA https://github.com/ostapenkor/MotivCellScopeApiServices.git
cd MotivCellScopeApiServices
git branch --show-current
```

Последняя команда должна показать `KOLYA`. Папка `MotivCellScopeApiServices` создаётся внутри текущей папки терминала; если такая папка уже есть, выберите другое место или другое имя для клона.

Если репозиторий уже скачан и в рабочей папке нет несохранённых изменений:

```powershell
git status
git fetch origin
git switch KOLYA
git pull --ff-only origin KOLYA
```

Сохраните свою работу до смены ветки. Если Git сообщает о конфликте, локальных изменениях или расходящихся коммитах, не применяйте `reset --hard`: для просмотра макета можно сделать отдельный клон командой выше.

Без Git можно открыть https://github.com/ostapenkor/MotivCellScopeApiServices/tree/KOLYA и выбрать **Code → Download ZIP**, затем распаковать архив целиком. Нужны не только HTML, но и соседние JS/CSS, `data` и `api`.

## 2. Выбрать один способ запуска

Ниже три альтернативы. Не запускайте их одновременно на одном порту. Для самого мониторинга не нужны .NET, MariaDB, Excel, npm или Visual Studio.

### Способ A: Docker — HTML и PHP без установки PHP на компьютер

Нужны установленный Docker Desktop с запущенным Linux engine и команда `docker compose`. Проверка:

```powershell
docker version
docker compose version
```

Из корня скачанного репозитория:

```powershell
docker compose -f prototypes/monitoring/compose.yml up -d
```

При первом запуске Docker скачает официальный образ `php:8.4-cli-alpine`, поэтому нужен интернет. После запуска откройте:

**http://127.0.0.1:5092/?transport=php**

Именно `?transport=php` включает получение JSON через PHP-обработчик. Без этого параметра тот же интерфейс читает демонстрационный JSON напрямую. В обоих случаях данные остаются демонстрационными.

Проверка PHP отдельно: откройте в браузере

http://127.0.0.1:5092/api/monitoring.php?action=cells

Должен появиться JSON с полями `mode: "demo"`, `asOf`, `gridVersion`, `regions`, `cells`. Логин и пароль для этого отдельного демо не нужны.

Состояние, журнал запуска и остановка:

```powershell
docker compose -f prototypes/monitoring/compose.yml ps
docker compose -f prototypes/monitoring/compose.yml logs --tail 30
docker compose -f prototypes/monitoring/compose.yml down
```

После изменения HTML/CSS/JS достаточно обновить страницу. Исходники подключены к контейнеру как папка для чтения, отдельная сборка образа не требуется.

### Способ B: PHP уже установлен

Из корня репозитория:

```powershell
cd prototypes/monitoring
php --version
php -l api/monitoring.php
$env:MONITORING_MODE = 'demo'
php -S 127.0.0.1:5092 -t .
```

Используйте современную поддерживаемую версию PHP; для этой инструкции контейнер использует PHP 8.4. Команда `php -l` должна сообщить об отсутствии синтаксических ошибок. Последняя команда запускает сервер и занимает терминал — не закрывайте его, пока пользуетесь страницей.

Откройте **http://127.0.0.1:5092/?transport=php**. Остановка — `Ctrl+C`. В PowerShell переменную можно удалить командой `Remove-Item Env:MONITORING_MODE`.

Для Linux/macOS вместо строки `$env:...` используйте `export MONITORING_MODE=demo`; остальная команда PHP такая же.

### Способ C: только посмотреть интерфейс через Python

Этот способ не исполняет PHP, зато позволяет быстро посмотреть карту.

```powershell
cd prototypes/monitoring
py -3 -m http.server 5092 --bind 127.0.0.1
```

Если команды `py` нет, при установленном Python 3 попробуйте:

```powershell
python -m http.server 5092 --bind 127.0.0.1
```

Откройте **http://127.0.0.1:5092/** — без `?transport=php`. Терминал держите открытым, остановка — `Ctrl+C`. Двойной щелчок по `index.html` не заменяет сервер: браузер может запретить загрузку JSON через `file://`.

## 3. Как убедиться, что всё работает

1. Открылась вкладка «Мониторинг сети» и видна пометка о демонстрационных БС.
2. На карте есть Свердловская и Курганская области, ХМАО и ЯНАО.
3. Выберите регион и состояние «Критическая проблема»: число ячеек и отображение должны измениться.
4. Нажмите на окрашенный гексагон: справа появятся вымышленные БС, их статусы и время обновления.
5. Нажмите «Сбросить фильтры» и «Вся область». Можно найти станцию по её демонстрационному коду.
6. В PHP-режиме прямая ссылка `api/monitoring.php?action=cells` возвращает JSON. Успешное отображение Python-демо само по себе не доказывает работу PHP.

Не требуется сравнивать конкретное число красных ячеек с настоящей сетью: это искусственный набор для проверки интерфейса.

## 4. Что где редактировать

| Файл | Назначение |
| --- | --- |
| `index.html` | Исходная страница лиды с доработанной вкладкой мониторинга |
| `monitoring.css` | Оформление вкладки, карта, карточка, адаптация к ширине окна |
| `monitoring.js` | Загрузка JSON, отрисовка, фильтры, выбор ячейки |
| `monitoring-config.js` | Выбор транспорта: статический JSON или PHP по параметру URL |
| `api/monitoring.php` | PHP-заглушка и места подключения настоящего API |
| `data/monitoring-demo.json` | Искусственные станции, состояния и время снимка |
| `data/map.json` | Фиксированная геометрия сетки и регионов для SVG |
| `data/regions.geojson` | Открытые исходные контуры четырёх регионов |
| `DATA-SOURCES.txt` | Источники и лицензия геоданных |
| `compose.yml` | Отдельный запуск PHP-демо в Docker |

HTML/CSS/JS не требуют сборки. Не меняйте `id` ячеек и `gridVersion` только в одном JSON: данные и геометрия должны соответствовать друг другу.

## 5. Где дописать PHP и подключить REST

Откройте `api/monitoring.php` и найдите комментарии:

- **`TODO_AUTH`** — проверить серверную сессию и права пользователя.
- **`TODO_REST`** — выполнить серверный запрос к вашему C# REST API и преобразовать его ответ в согласованный JSON.
- **`TODO_SERVER`** — подготовить разрешённые сведения по гексам; точные координаты и закрытые соответствия БС → гекс держать на сервере.

Получается цепочка **браузер → PHP → C# REST API → БД**. Уже существующие правила C# повторно на PHP не переписываем. Точные правила новых аномалий нужно согласовать отдельно: показатель, порог, длительность, приоритет и устаревание данных.

Сейчас PHP поддерживает только демо. Если задать `MONITORING_MODE` отличным от `demo`, он намеренно возвращает **503 `REST_NOT_CONNECTED`**. Изменение переменной не подключает API автоматически: сначала необходимо реализовать отмеченные места. Браузер не заменяет ошибку API вымышленными успешными данными.

Есть два GET-запроса: `action=cells` возвращает набор ячеек; `action=cell&id=...` — карточку одной ячейки. Пример ID можно взять из ответа `cells`, не нужно придумывать его вручную. HTTP 400 означает неверные параметры, 404 — неизвестную ячейку. Демо отдаёт списки станций целиком; в рабочем варианте перечень и подробности передаются только в пределах прав пользователя.

## 6. Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `php`, `py`, `python` не найдены | Выберите способ с Docker или установите нужный интерпретатор из официального источника; перезапустите терминал после изменения PATH |
| Docker сообщает, что engine недоступен | Запустите Docker Desktop и дождитесь готовности Linux engine |
| Порт 5092 занят | Остановите предыдущий Python/PHP-сервер или контейнер демо; это три альтернативных способа запуска |
| 404 на главной или нет CSS/JSON | Запускайте из `prototypes/monitoring`; убедитесь, что скачана вся папка, а не один HTML |
| Ошибка JSON при `?transport=php` | Python PHP не исполняет. Используйте Docker/PHP или уберите параметр для статического демо |
| 503 `REST_NOT_CONNECTED` | Верните `MONITORING_MODE=demo` для просмотра заглушки; настоящее подключение ещё нужно написать |
| Вместо новой версии виден старый экран | Проверьте ветку KOLYA, выполните `git pull --ff-only origin KOLYA` и обновите браузер с `Ctrl+F5` |
| В интерфейсе нет изменений после сохранения файла | Проверьте, что редактируется именно скачанная папка, которую обслуживает запущенный сервер |

Встроенный сервер PHP используется для локальной разработки и демонстрации. Команды публикуют порт только на `127.0.0.1`.

## 7. Если нужен основной журнал с настоящим C# API

Это другой модуль того же репозитория. Он запускается из корня через `docker-compose.case.yml`, обычно на порту 5090. У него есть отдельная MariaDB, роли и импорт Excel. Подробная инструкция: [docs/journal/DATABASE.md](../../docs/journal/DATABASE.md).

Мониторинг на 5092 сейчас является отдельным демонстрационным интерфейсом. Запуск основного журнала сам по себе не подключает к нему карту. Логин `admin` основного журнала и пароль из своей `.env.case` к отдельному демо мониторинга не относятся.

Источники команд: [PHP — встроенный сервер](https://www.php.net/manual/en/features.commandline.webserver.php), [официальный Docker-образ PHP](https://hub.docker.com/_/php).
