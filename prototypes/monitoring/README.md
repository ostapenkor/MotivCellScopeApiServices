**Начните с [подробной инструкции запуска](START-HERE.md).**

# Демонстрация мониторинга

Изолированный макет: HTML/CSS/JS → PHP → C# REST JSON. Сейчас PHP отдаёт только синтетические данные из `data/monitoring-demo.json`. Подключение к настоящему REST не выполнено. Основное приложение на C# (`http://localhost:5090`) не изменено.

## Запуск

На машине PHP не найден в PATH; синтаксис и работа обработчика проверены в официальном Docker-образе php:8.4-cli-alpine. При установленном PHP можно запустить из этой папки:

```powershell
php -S 127.0.0.1:5092 -t .
```

Откройте `http://127.0.0.1:5092/`. Для статической демонстрации интерфейса можно использовать `python -m http.server 5092 --bind 127.0.0.1`; Python не выполняет PHP, поэтому интерфейс использует демонстрационный JSON напрямую.

## Контракт заглушки

- `GET api/monitoring.php?action=cells` (действие по умолчанию): весь демонстрационный JSON.
- `GET api/monitoring.php?action=cell&id=...`: `{mode, asOf, gridVersion, cell}` для одного гекса. Фильтры региона и статуса выполняются интерфейсом.
- Конверт данных: `{mode:"demo", asOf:"ISO 8601 UTC", gridVersion:"demo-mercator-hex70-v1", regions:[{id,name}], cells:[{id,regionId,status,updatedAt,stations:[{id,name,status,issue?,updatedAt}]}]}`.
- Статусы: `critical`, `warning`, `ok`, `unknown`. Идентификаторы состоят из 1–128 ASCII-букв, цифр, `_`, `.`, `:`, `-`; первый символ — буква или цифра.
- Ответы имеют `Cache-Control: no-store`; ошибки возвращаются JSON. Только GET, без разрешающего CORS-заголовка. Неизвестный гекс возвращает 404, неверные параметры — 400, отсутствующие/повреждённые данные — 503.
- Геометрия регионов находится отдельно в `data/regions.geojson`. Готовая геометрия сетки находится в data/map.json. Её gridVersion и идентификаторы ячеек должны совпадать с ответом JSON. Это демонстрационная схема, не расположение настоящих БС.

## Подключение настоящих данных

Любое значение переменной окружения `MONITORING_MODE`, кроме `demo`, возвращает 503 с `REST_NOT_CONNECTED`. В заглушке нет рабочего прокси и настоящего адреса upstream. В `api/monitoring.php` оставлены точки интеграции:

- `TODO_AUTH`: проверить серверную сессию и права на каждый запрос. Скрытие элементов по роли в JS не обеспечивает контроль доступа.
- `TODO_REST`: обратиться к разрешённому C# REST с сервера по фиксированному адресу из allowlist; секреты получить из окружения и не передавать браузеру.
- `TODO_SERVER`: хранить соответствия БС → гекс и точные координаты на сервере. Браузеру передавать разрешённые агрегаты; включать перечень БС только при наличии соответствующих прав.

В текущей книге нет инвентарного списка БС и координат. Нельзя выводить из неё вымышленные географические привязки и представлять их как настоящие. Для определения реальных аномалий отдельно нужны метрики, пороги/SLA, временные окна и правила обработки отсутствующих или устаревших измерений. Демонстрационные статусы не являются результатом такого анализа.


## Что готово и что проверено

Доработана вкладка мониторинга исходного HTML: четыре региона, фильтры, поиск БС, масштабирование, выбор гексагона, карточка со списком станций, отдельные состояния отсутствующих/устаревших данных. Остальные вкладки сохраняют статус исходного макета; их кнопки и переключатель ролей не подключены к API.

Проверены синтаксис JS, уникальность ID, соответствие геометрии и данных, отсутствие координат/адресов в фиктивных записях БС, фильтр региона и критичности, открытие списка БС и отсутствие горизонтального переполнения в проверенном окне. В консоли браузера ошибок не обнаружено. PHP-обработчик проверен в Docker: список ячеек, карточка, JSON/no-store, ошибки 400/404/405 и синтаксис без ошибок.

Демо использует собственную фиксированную сетку в проекции Mercator. 70 км — радиус в координатах проекции, а не одинаковое наземное расстояние. Это не H3 и не утверждённая промышленная схема обезличивания. Масштабирование меняет вид, а не ячейки/ID. Крайние гексы могут пересекать границы; регион в демо определяется по центру. Для рабочего подключения необходимо согласовать версию сетки, разрешение и правила пограничных ячеек на сервере.

Порог устаревания 10 минут — демонстрационное правило. В демо свежесть считается относительно asOf снимка; живой режим использует текущее время. Правила реальных аномалий и их приоритета должны прийти из единственного серверного источника логики. Отсутствие сигнала не означает норму.

## Экономный следующий этап

1. Согласовать один JSON-контракт и расположение логики: PHP как серверная прослойка к существующему C# REST.
2. Подключить один endpoint и один реальный обезличенный набор, проверить фильтр и карточку.
3. Затем отдельно делать правила аномалий, авторизацию и интеграцию с журналом. Полный прогон проекта нужен при изменении общих контрактов, авторизации и БД; для локальной верстки достаточно адресной проверки.
