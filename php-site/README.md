# МОТИВ — тонкий PHP-клиент MotivCellScope API

Все файлы сайта находятся в одной папке `php-site/`. Папка не входит в C#-проект API.

```text
php-site/
  index.php          один контроллер и HTML-представления четырёх вкладок
  ApiClient.php      синхронные запросы cURL к фиксированным API-маршрутам
  assets/style.css   общие стили, адаптивность и анимации
  assets/ui.js       локальная проверка форм и состояния кнопок
  Dockerfile
  README.md
```

Вкладки: дашборд, журнал инцидентов, отчёты, мониторинг. HTML генерирует PHP. JavaScript не обращается к API; нет `fetch`, npm, сборщика или стороннего UI-фреймворка. Данные, справочники, расчёты и проверки прав принадлежат API. При недоступности API сайт показывает ошибку, а не демонстрационные показатели.

## Запуск

Из корня репозитория, после настройки `.env` по [инструкции запуска](../docs/START-HERE.md):

```powershell
docker compose --env-file .env -f docker-compose.yml up --build -d
```

Адрес сайта при стандартных портах Compose: `http://localhost:5092`. В контейнере PHP обращается к `http://api:8080`. `api` должен быть сетевым псевдонимом сервиса ASP.NET API в той же Docker-сети.

Отдельный запуск с установленными PHP 8.4 и расширением cURL, из папки сайта:

```powershell
$env:API_BASE_URL = 'http://127.0.0.1:8080'
php -d display_errors=0 -S 127.0.0.1:5092 -t .
```

Проверка окружения: `php -v`, `php -m` (в списке нужен `curl`). Проверка синтаксиса: `php -l index.php`, `php -l ApiClient.php`. Официальный образ `php:8.4-cli-alpine` уже содержит cURL (проверено командой `php -m`). Dockerfile запускает встроенный PHP-сервер на порту 8080; этот сервер предназначен для локального запуска и демонстрации. При размещении за HTTPS задайте `APP_COOKIE_SECURE=1`; вне локальной среды PHP следует запускать за обычным веб-сервером.

## Вход и роли

Форма входа использует уже существующий `POST /api/auth/login`. На каждой открытой странице PHP проверяет сессию через существующий `GET /api/auth/me`. Логин и пароль выдаёт администратор актуальной БД. Пароль MariaDB не является паролем учётной записи сайта. Новая авторизация, управление пользователями и административная панель в PHP не реализованы.

- `engineer`: просмотр, фильтрация, CSV.
- `operator`, `admin`: дополнительно создание, изменение и удаление инцидентов.

JWT хранится только на PHP-сервере в сессии. Браузер получает только идентификатор сессии в `HttpOnly`, `SameSite=Lax` cookie. Токен не попадает в HTML, JavaScript или localStorage. После входа и выхода идентификатор сессии обновляется. Вход, выход и изменения отправляются методом POST с CSRF-токеном. Роль в интерфейсе не заменяет проверку прав в API.

## Контракт данных

PHP выполняет синхронные cURL-запросы: соединение — до 5 секунд, весь запрос — до 30 секунд. Хост задаёт только серверная переменная `API_BASE_URL`; произвольные адреса или маршруты из параметров браузера не принимаются. HTTP-перенаправления API не разрешены.

Используемые маршруты:

- `GET /api/reference/all` — списки для фильтров и формы.
- `GET /api/incidents`, `GET /api/incidents/{id}` — журнал и карточка.
- `POST /api/incidents`, `PUT /api/incidents/{id}`, `DELETE /api/incidents/{id}` — изменения с проверкой прав API.
- `GET /api/incidents/export` — детальный CSV.
- `GET /api/reports/incidents-summary`, `GET /api/reports/available-periods` — сводка и период.
- `GET /api/reports/incidents-export?groupBy=...` — сводный CSV.
- `GET /api/monitoring/summary`, `/api/monitoring/anomalies`, `/api/monitoring/network-elements` — мониторинг.

Время в интерфейсе и запросах — **UTC**. Конечная дата фильтра включительна: PHP передаёт в API начало следующего дня как исключительную границу `to`. Время начала/окончания формы передаётся в ISO 8601 с суффиксом `Z`. Начало обязательно; пустое окончание означает открытый инцидент.

Для `akb`, `dgu`, `prostoy` используется `ЧЧ:ММ:СС`, включая часы больше 24, до ограничения MariaDB `838:59:59`. Пустое значение означает неизвестную длительность. `numbRbs` — строка от 1 до 10 000, кириллическая `С` или неизвестное пустое значение. `lenght`, `commonProstoy`, автор и поля аудита показывает и рассчитывает сервер. Форма изменения отправляет `expectedUpdatedAt`; ответ API 409 сохраняет введённые данные и предлагает обновить запись. Название сетевого элемента определяется API из выбранного ID.

Фильтры распространяются на журнал, сводки и CSV. В CSV не добавляются фиктивные нули вместо неизвестных длительностей; расчётные исключения показываются отдельно. Выборка журнала имеет постраничный вывод. Список элементов для формы загружается из API (до 10 000); в мониторинге показаны первые 200 элементов с явным количеством. Все значения из API и форм экранируются при выводе HTML.

## Мониторинг и карта

В актуальной схеме нет измеренного показателя доступности. Если API возвращает `avgAvailability: null`, сайт пишет «Нет исходных данных». `trafficActivityPct` показывается отдельно как «Активность трафика»; этот прокси не называется доступностью. CSSR, DCR, трафик и количество объектов берутся из API без демонстрационных значений.

**Карта — явная заглушка.** Точные координаты по умолчанию скрыты в API (`Monitoring__ExposeCoordinates=false`). Режим карты и допустимую точность нужно согласовать отдельно. Заглушка не содержит вымышленных станций, а реальные элементы доступны в таблице. Старый автономный HTML-прототип с демонстрационной картой не включён в этот PHP-сайт.

При ошибке сохранения данные формы сохраняются в ответе. После успешных изменений используется перенаправление POST → GET; повторное открытие страницы не отправляет изменение ещё раз. Ошибки API 400/401/403/409 и сетевые таймауты показываются пользователю без серверных секретов.
